# 취준 Radar (v8.1.25)

**배포 URL: https://chwijun-radar.vercel.app**

2026 하반기 취업 지원·전형·마감 통합 관리 PWA. 실행물은 정적 사이트이며,
배포 때 승인 기준선 검증과 정적 파일 선별만 수행합니다.

## 구조
```
index.html              화면 마크업
styles.css              스타일 (v2 디자인 유지 + 모바일/PWA 보강)
data.js                 기업 참고 DB 및 앱 상수 (예시 지원 데이터 없음)

manifest.webmanifest    PWA manifest
icons/                  192·512·maskable·apple-touch
vercel.json             캐시/보안 헤더
```

`release-lock.json`과 다르거나 폐기된 개인 실행계획 주입 코드가 다시 들어오면 빌드가 실패한다.
Vercel에는 검증된 정적 파일만 들어 있는 `.vercel-static`이 배포된다. 정상 기능을 수정해
새 버전을 낼 때는 전체 회귀검사 후 버전과 `release-lock.json`을 의도적으로 함께 갱신한다.

## 상태와 진행률은 손으로 넣지 않는다 (v5)

**지원 건 = 회사 + 직무.** 같은 회사·직무의 일정이 하나로 묶이고, `+ 전형 추가` 로
다음 단계를 붙이면 캘린더에 자취가 그대로 남는다.

사람이 입력하는 건 **각 전형의 결과(`result`)** 하나뿐이다.

| 단계 | 고를 수 있는 결과 |
|---|---|
| 서류 마감 `apply` | 아직 / 제출 완료 / 통과 / 탈락 |
| 인적성·면접·최종 `test` `interview` `final` | 아직 / 통과 / 탈락 |
| 공고오픈·설명회·발표·자격 | 아직 / 참석·완료 |

여기서 지원 건의 상태가 자동 계산된다 (`app.js` 의 `deriveStatus`).

```
누구든 탈락              -> 불합격 (회색조, 목록 맨 아래)
최종발표 통과            -> 최종합격   100%
검사/면접 일정이 지남     -> 검사·면접   80%
서류 통과                -> 서류합격    55%
서류 제출 또는 마감 지남  -> 지원완료    30%
그 외                    -> 지원예정     0%
보류 토글                -> 보류
```

진행률(`data.js` 의 `STATUS_PROGRESS`)도 이 상태에서 나온다.
회사마다 전형 개수가 달라도 같은 잣대로 비교된다.

지난 일정인데 결과가 비어 있으면 카드에 `9/11 인적성·역량검사 결과는? [통과] [탈락]` 한 줄이 뜬다.
`통과` 를 누르면 다음 전형 일정을 바로 등록할지 물어본다.

`events[].status` 와 `events[].progress` 는 더 이상 쓰지 않는 잔재 필드다. 읽지 말 것.

## 자동 채용 레이더 → 검토함 → 캘린더
v8.1.8부터는 별도 `radar_feed_items`의 공개 채용공고를 앱 시작·온라인 복귀 시 자동 확인한다.
v8.1.9에서는 자동화 이후 불필요해진 수동 레이더 가져오기를 더보기에서 제거하고, 기기간 동기화를 `휴대폰과 연결`로 명확히 표시한다. 서버 동기화는 revision 기반 CAS를 사용한다.
v8.1.10에서는 공용 feed 수집·필터 범위를 R&D, SW/HW, 생산·공정, 품질, 디자인, 법무까지 넓힌다. 사용자가 직접 입력한 `R&D(연구개발)` 같은 표기도 동의어로 매칭한다.
v8.1.11에서는 R&D 희망 직무에 시스템설계, SW, AI, 애플리케이션, 반도체 공정설계까지 인접 후보로 포함한다.

v8.1.12부터 새 Radar는 이 기기에만 저장된 상태로 시작한다. 기기간 동기화는 필요할 때 `더보기 → 휴대폰과 연결`에서 사용자가 직접 켜며, 기존 Radar 불러오기와 이미 연결된 사용자의 동기화 설정은 그대로 유지된다.

v8.1.13은 설치형 PWA가 열린 상태에서도 새 배포를 주기적으로 확인하도록 보강했다. 새 공고 화면은 마지막 수집 건수가 아닌 현재 검토 대기 건수를 표시하고, 승인·제외 버튼의 실제 범위를 명확히 적는다.

v8.1.14는 닫힌 바텀시트를 키보드와 스크린리더 탐색에서 제외하고, 열기/닫기 포커스 복원과 Esc 닫기를 추가했다. 현재 하단 탭을 보조기기에 전달하며 보조 글자 대비와 작은 핵심 터치 영역을 WCAG 2.1 AA 기준에 맞게 보강했다.

v8.1.15는 유효한 공고를 정상 게시했지만 목표 확인 기업 수에 못 미친 실행을 전체 `갱신 실패`로 표시하던 문제를 수정했다. 실제 전송 실패만 재시도 가능한 실패로 표시하며, 부분 확인은 `업데이트됨 · 일부 사이트 확인 지연`으로 안내한다.

v8.1.16은 지원 기기에서 홈 화면 앱 아이콘 숫자를 실제 검토 대기 공고 수와 맞춘다. 또한 `연구`, `연구 쪽`, `기술연구`, `R&D(연구개발)` 희망 직무를 연구개발 인접 직군(설계·공정·소재·시험·평가·AI/SW 등)까지 매칭하되 영업·경영 직군의 과다 유입은 막는다.

v8.1.21은 새 공고 맞춤 필터에 상권·점포개발·리징·부동산개발·상업공간기획을 연결하고, 공채에서 쓰는 `경영일반` 표기를 사업·전략기획 희망 직무와 연결한다. 매장 운영·현장 관리까지 무분별하게 넓히지 않고 공간 및 사업개발 직무만 포함한다.

v8.1.22는 폐기된 v8.1.19의 개인 실행계획 자동 주입 코드와 원본 데이터를 제거한다. 이미 주입된 항목은 고정 ID로만 정리하고 사용자 직접 일정은 보존한다. 이후 배포는 이 복구 기준선에서만 만든다.

v8.1.23은 기존 홈과 지원 데이터를 그대로 유지하면서 영문 직무명 및 공개 feed의 `match_terms`를 희망 직무 필터에 반영한다. 공식 제목이 영문이거나 `일반직군`처럼 묶여 있어도 검증된 직무 방향으로 검토함 후보가 누락되지 않는다.

v8.1.24는 공개 채용 feed와 상태 조회에 `cache: 'no-store'`를 적용해 새 공고는 갱신됐지만 마지막 실행 시각만 과거 값으로 남는 브라우저 캐시 불일치를 막는다. 서비스워커와 정적 자원 버전도 동일한 버전으로 정렬한다.

v8.1.18은 기존 Pretendard를 유지하면서 과한 굵기와 좁은 자간을 완화해 모바일 가독성과 자연스러운 정보 위계를 개선한다. 기능·데이터·eligibility·동기화 동작은 v8.1.17과 동일하다.

v8.1.17은 신규 온보딩 직후 최초 feed를 가져오고, 신규 상태의 feed map 누락을 보완한다. 개인 제외 규칙, 변경·마감·비활성 공고 처리, feed 최신성 표시를 바로잡고, 모바일 지원 정보 수정창 가림과 일정 편집의 회사·직무 우회를 막는다. 로컬 저장 실패 상태는 원격에 올리지 않으며 큰 암호화 payload와 동기화 room 전환을 안전하게 처리한다.
지원 프로필의 직무와 맞는 새 후보만 검토함에 넣고, 자동 승인하지 않는다. 기기간 동기화와 오류 상태도 분리한다.

**가져온 공고는 캘린더에 바로 들어가지 않는다.** `새 공고` 탭(검토함)에 쌓이고,
회사·직무·주요업무(JD)·자격요건·영어요건·전형일정을 확인한 뒤 사용자가 결정한다.

- `캘린더에 추가` — 켜져 있는 일정만 events 로 들어간다. 전형 일정 칩을 눌러 개별로 끌 수 있다
- `제외` — `state.dismissed` 에 `회사|직무` 로 기록되어 **다음 가져오기부터 자동으로 걸러진다**.
  되돌리려면 검토함 우측 상단 `제외 목록 초기화`
- 추가된 항목의 메모에는 note·JD·자격요건이 합쳐져 들어간다

- 코드블록(```json), 앞뒤 설명문, 끝 쉼표, 한글 stage(`서류마감`/`인적성`/`면접` 등)를 모두 알아서 처리한다
- **같은 회사+직무+날짜+단계는 중복으로 건너뛴다** — 매일 돌려도 안전
- **보정 제외 규칙(APR·롯데백화점·롯데캐피탈 등)에 걸리는 항목은 자동 차단**된다. GPT가 실수로 넣어도 앱이 막는다
- 기존 항목은 절대 덮어쓰지 않는다
- 프롬프트 원문: `data.js` 의 `GPT_PROMPT`, 별도 파일 `GPT_레이더_프롬프트.md`
- 검토함 데이터: `state.inbox` (검토 대기), `state.dismissed` (제외한 `회사|직무` 목록)
- 받아들이는 필드 별칭: `data.js` 의 `STAGE_ALIAS` / `TIER_ALIAS`

동기화를 켜두면 PC에서 붙여넣은 결과가 휴대폰으로 자동 전파된다.

## 기기간 동기화
앱 상단 `동기화` → Supabase Project URL / anon key / 동기화 키 입력.
설정하지 않으면 데이터는 그 기기의 localStorage 에만 저장되고, `백업 → 불러오기` 로 옮길 수 있습니다.

필요한 테이블:
```sql
create table if not exists radar_state (
  id text primary key,
  data jsonb not null,
  updated_at timestamptz not null default now()
);
alter table radar_state enable row level security;
create policy "radar anon rw" on radar_state
  for all to anon using (true) with check (true);
```

## 공고 확인 기준

매일 레이더가 공개 채용시장을 확인해 공용 feed를 갱신하고, 각 브라우저는 자기 희망 직무와 제외 규칙으로 후보를 걸러 검토함에 넣습니다. 최종 지원 반영은 항상 사용자가 승인합니다.

가져오기 JSON 형식:
```json
{
  "items": [ { "company": "...", "role": "...", "tier": "S", "url": "https://...",
               "schedule": [ { "stage": "apply", "date": "2026-09-18", "time": "15:00" } ] } ],
  "checks": [ { "company": "SK하이닉스", "url": "https://talent.skhynix.com",
                "checkedAt": "2026-09-09", "status": "found | none | fail", "note": "한 줄 근거" } ]
}
```
예전처럼 배열 `[ {...} ]` 하나만 붙여넣어도 그대로 동작합니다.

### 미검증 표시
공고에 `url` 이 없거나 GPT 가 note 앞에 `[미검증]` 을 붙였으면
검토함 카드에 **미검증** 배지와 경고가 뜹니다. 캘린더에 넣기 전에 직접 확인하라는 뜻입니다.

### 알아둘 것 — 자동 수집의 한계
사람인·잡코리아는 크롤링을 막고, 기업 채용 사이트는 대부분 JS·로그인 뒤에 있습니다.
**«하루 한 번 전부 긁어와서 절대 안 놓친다»는 어떤 방법으로도 보장되지 않습니다.**
그래서 보장하는 척하지 않고, 대신 ① 지원 목록을 프롬프트에 강제로 박고
② 확인 안 된 곳을 결과에 남기고 ③ 출처 없는 공고를 미검증으로 표시하는 쪽을 택했습니다.

1. `bash servers.sh`
2. `node symcheck.mjs` — 여기서 빈 화면이 나오면 배포 금지
3. 전체 스위트 실행
4. 새 CSS 클래스를 만들었다면 기존 이름과 겹치는지 `grep` (실제로 `.dot` 충돌이 있었다)
